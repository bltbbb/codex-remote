# 阶段 2：响应式 Web UI 完成报告

完成日期：2026-08-02

## 已实现体验

- React 19、TypeScript、Vite 响应式单页应用。
- 按电脑工作目录分组的历史会话侧栏、搜索和游标分页。
- 新建会话、选择历史、继续发送、停止与失败重试。
- 用户消息、最终回复、推理摘要、计划、终端、工具调用和文件差异卡片。
- 最终回复出现前，过程回复、思考、工具、命令和文件操作按原始事件顺序平铺；第一段最终回复出现后，完整过程自动折叠为“已处理 + 总耗时”，完成后可手动重新展开。
- 命令、文件和权限审批面板。
- 断线重连、事件确认与重放。
- iPhone 14 Pro Max 的 430×932 断点、侧栏抽屉、无横向溢出、底部安全区和深色模式。
- 非 HTTPS 局域网地址兼容，不依赖 `crypto.randomUUID` 或桌面专属浏览器 API。

## 阶段 4 真机体验修订

- 历史摘要保存在手机本地，连接后先即时展示并与 Bridge 预热结果后台同步。
- 历史列表与当前会话并行请求；初次列表和会话读取分别显示骨架屏及明确状态。
- 运行中过程在尚未收到第一项时仍保持“正在准备”，随后按思考、工具、命令、修改和回复阶段稳定切换。
- 过程标题显示实时累计时间，完成后保留总耗时并沿用自动折叠行为。
- 英文内部推理摘要默认转换为简明中文，原始文本只在用户主动展开“查看原始摘要”后显示。
- 输入区使用固定尺寸 SVG 图标；用户消息、回复、推理和过程输出均限制在视口内，命令输出只在自身区域横向滚动。
- `commentary` 过程回复与 `final_answer` 最终回复按阶段分流，避免上方过程增长反复把下方回复顶走。
- 自动跟随只改变会话容器的 `scrollTop`，不再通过 `scrollIntoView` 牵动 Safari 页面视口和底部输入区。
- 移动端顶部状态、时间线和输入框统一保留 34px 右侧保护距离；发送按钮清除 Safari 默认内边距并校正箭头的视觉中心。
- 应用宽度同时跟随 `visualViewport.width` 和横向偏移，不再假设布局视口与 Safari 实际可见宽度始终相同；站点缩放或浏览器栏状态变化时，顶部状态、骨架和输入框仍以可见右边界为准。
- Safari 从后台返回时主动重建可能已经失效的 WebSocket，但保留当前会话状态，只重放漏掉的事件并静默刷新列表；正常恢复不再重新请求 `thread.read` 或显示骨架。
- Safari 回收整个页面进程时，从当前标签页 `sessionStorage` 中的临时快照立即恢复最多 12 个回合，再在后台读取真实线程；快照最大 1.5 MB，不写入长期本地存储。

## 浏览器实测发现并修复的问题

1. 从局域网 IP 打开页面时，固定的 `127.0.0.1` WebSocket 会指向手机自身；现改为自动使用页面主机名。
2. `8787` 被本机其他服务占用；项目使用独立端口 `18787`，Web 开发端口使用 `15173`。
3. 局域网 HTTP 不提供 `crypto.randomUUID`；协议层增加 `getRandomValues` UUID v4 回退。
4. 移动侧栏遮罩与关闭按钮最初使用相同无障碍名称；现已拆分为唯一名称。
5. E2E 模拟器连接增加隔离模式，避免不同浏览器项目重放彼此未决审批。
